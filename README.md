# Ontology 🧬

> El código deja de ser el manuscrito sagrado. Se vuelve el residuo compilado de una realidad bien descrita.

Ontology is a semantic compiler for operational interfaces.

## Architecture: The 10 Semantic Layers

```text
Reality
   │
   ▼
 1. Canon            (Universal truths & operational laws)
 2. Domain           (Entities, attributes, and their relationships)
 3. Task             (User intent and state transitions)
 4. Info Arch        (Hierarchical navigation and flow)
 5. Interaction      (Human-computer boundary behaviors)
 6. Component Map    (Semantic assignment of UI elements)
 7. Layout           (Spatial distribution and priority)
 8. Visual Tokens    (Aesthetic system and branding)
 9. Data Binding     (State mapping to UI properties)
10. Render Target    (Final compiled artifact framework)
   │
   ▼
 Code
```

* **Canon**: Universal truths, constraints, and business rules that govern the entire system.
* **Domain**: The literal objects of reality modeled into explicit entities and attributes.
* **Task**: The specific actions an actor takes to mutate the state of the domain.
* **Info Architecture**: The cognitive structure and pathing required to access tasks.
* **Interaction**: The behavioral contracts between the human and the machine.
* **Component Mapping**: The translation of semantic intent into abstract UI components.
* **Layout**: The spatial prioritization of information based on cognitive load.
* **Visual Tokens**: The atomic aesthetic variables that style the interface.
* **Data Binding**: The explicit plumbing connecting domain state to interface properties.
* **Render Target**: The final, ephemeral syntax (e.g., React, TypeScript) generated by the compiler.

## Project Structure

* `/ontology` - **The Source of Truth**: The semantic definitions, rules, and structures. Hand-authored or generated via the LLM pipeline, this is the actual system.
* `/src/schemas` - **The Rigid Boundaries**: Strict Zod schemas that validate the ontology. The structural laws the semantic nodes must obey.
* `/src/generated` - **The Compiled Residue**: The final application code. This directory is a build artifact, not the source.

## The Asymmetric LLM Pipeline

Ontology utilizes an asymmetric, dual-engine LLM pipeline to process semantic structures. It pairs fast, deterministic local models for structured parsing with large, deep-thinking models for semantic critique and validation.

```yaml
# ontology.config.yaml
llm:
  parser:
    provider: ollama
    model: qwen2.5-coder
    temperature: 0.0
    role: "Deterministic structure generator"
  critic:
    provider: deepseek
    model: deepseek-r1
    temperature: 0.7
    role: "Semantic reasoning and constraints validation"
```

## Installation & Setup

```bash
npm install
npm run build
onto init
```

## Quickstart / CLI Usage

* `onto init` - Initializes the ontology workspace and seeds the initial directory structure.
* `onto plan "<intent>"` - Engages the asymmetric LLM pipeline to map a natural language intent into a structured semantic plan.
* `onto build <view>` - Compiles a specific semantic view into its final Render Target artifact.
* `onto why <node>` - Traces the deterministic lineage of any compiled element back to its origin in reality.

```text
$ onto why views/HarvestConfirmation confirm_action.position

<path> confirm_action.position = "sticky_bottom"

Because:
1. task.actor = "operator"
2. context.environment = "wet_hands_or_gloves"
3. canon.rule[operator_mode_requires_large_tap_targets] = true
4. canon.rule[primary_action_always_visible] = true

Generated in: ontology/views/HarvestConfirmation.ast.yaml
Compiled to: src/generated/views/HarvestConfirmation.tsx
```
