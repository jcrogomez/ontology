Drafts live under `.ontology/work/drafts/<focalId>.draft.json` (ephemeral working state, NOT events); a `(draft pending)` indicator appears on the identity bar when a focal has a saved draft; `:propose` creates a `node_create` proposal inheriting the focal's level/kind and clears the draft on success. The full chain `walker → draft → proposal → apply → node` is replayable. State-store helpers (`readState`, `writeState`) gained an optional `cwd` parameter so callers can address an explicit project root; proposals/runs thread it through.
- Walker v1 PR-B (PR #100): `:run` integration. Dispatches a model run against the focal's assembled context, persists the result automatically, and renders it in a `:clearrun`-able panel below the focal cell. The walker stays interactive during dispatch — a "running" panel renders synchronously, then the result panel replaces it on resolve. Cache hits on the deterministic run id surface as `(cached)` with no second LLM call. `:run` accepts an optional provider arg (`mock` default, `ollama` for live local model). Errors (e.g. ollama unavailable) render as a red panel instead of crashing the TUI.
- Walker v1 PR-C (PR #101): `:plan` compile-plan preview + `onto compile plan <nodeId>` CLI surface. Pure helper `computeCompilePlan` (`src/runtime/graph/compile-plan.ts`) implements Kahn's topological sort over the hard-dependency edge family (`depends_on`, `inherits_from`, `refines`, `implements`, `uses_token`), detects dependency cycles with the unresolved set surfaced, and produces deterministic step order via alphabetical tiebreak. The walker renders the plan in a green panel (red on cycle) below the focal cell. Same helper used by both surfaces so scripts and the TUI agree on the order. Read-only — no artifact written, no event emitted. **Closes the Walker v1 milestone**; the actual compiler ships in Bootstrap 0.8.
- **Bootstrap 0.8 — Hello World (PR #102): the compiler ships.** `onto compile run <nodeId>` walks the topological plan and produces real artifacts at `.ontology/artifacts/generated/`. Each step persists a content-addressed `PersistedRun` and emits both `run_persisted` and `compilation_run` events; the audit chain `artifact → compilation_run → runId → run record → prompt hash → node` is replayable end to end. The mock provider acts as the **identity functor** for `task: code_sketch` (returns the prompt verbatim), making axiom 6 demonstrable offline; real Ollama is a non-identity functor through the same pipeline. New compile primitives live under `src/runtime/compile/` (manifestation-mapper, artifact-writer, compile-node, compile-plan-runner). Walker integration via `:compile [provider]`. `onto node create` now accepts `--manifestation` and `--language` so leaves can declare their compile target. `examples/hello-world/` ships a one-command demo that builds canon → ... → leaf, compiles, and runs the produced Python script: `npm run example:hello-world`. **Axiom 6 (compiler functor) and axiom 7 (code as compiled shadow) running concrete code.**
- Compiler hardening — code-fence stripping (PR #103): when `coordinates.manifestation === "code"`, `artifact-writer` strips a leading/trailing markdown code fence (and the optional language tag) so a model returning `\`\`\`python\nprint(...)\n\`\`\`` produces a runnable file rather than an unparseable artifact. Pure helper, transparent to the rest of the pipeline.
- Compiler hardening — language parse-check (PR #104): every code artifact is parse-validated against the node's declared `technical.language` after write. Failures emit a `validate_failed` step record with the parser stderr and abort the plan run. Provides a deterministic, model-agnostic floor on artifact quality.
- Compiler hardening — refinement-parent context threading (PR #105): per-node `compileNode` now receives the resolved refinement chain so each step's system prompt explicitly carries upstream `provides` tokens and parent prompts. Closes the long-standing "compiler does not thread upstream outputs" limitation.
- Walker — `:run` / `:compile` accept `--model` and `--ollama-host` (PR #106): the walker can now drive a specific Ollama model or a non-default host without leaving the TUI; the args round-trip through the same dispatcher path the CLI uses.
- Test reliability — vitest hookTimeout bumped to 30s (PR #107) to absorb tsx cold-start on the heavy CLI suite. No production code touched.
- Compiler — per-node `model.ref` routing (PR #108): when no `--provider` override is set on `onto compile run`, each node compiles via its own `technical.model.ref` resolved through the model registry. The registry path keeps the per-step run record honest about which model produced which artifact.
- Compiler — system-prompt format leak fix (PR #109): the assembled system prompt no longer renders inline `[id :: level]` brackets as plain text into the model body. Upstream context is now passed via XML `<context>` tags, which is both better for instruction-following models and prevents accidental leakage of internal notation into artifacts.
- Compiler hardening — optional `--runtime-check` (PR #110): after parse-validation, `onto compile run --runtime-check` executes the artifact under a wall-clock timeout (default 5000 ms, max 60000 ms) and surfaces non-zero exits, signal kills, and timeouts as `runtime_failed` step records. Off by default; a deterministic gate when you want artifacts to actually run.
- **Bootstrap 0.9 — Categorical Extensions (PR #111):** four additive runtime libraries land together, each with proven laws or property tests, and integrated into the existing kernel without modifying axioms 1–7. See [`CATEGORICAL_VISION.md`](CATEGORICAL_VISION.md) for the full nine-concept map.
  - `feat(query)` — Yoneda search by Hom-profile. `onto query` CLI matches every node whose actual profile is a superset of the query shape (kind / abstraction / plane / manifestation / status / branch + incoming / outgoing edge types + context-contract tokens). Pure matcher in `src/runtime/query/representable.ts`. Empty shape `{}` matches every node (the trivial Yoneda statement).
  - `feat(effects)` — `Result<T,E>` / `Effect<T,E>` / `EffectWithLog<T,E>` monad library with proven monad laws. `bindWithLog` concatenates logs even when the inner effect fails — log entries are write-only and survive failure, exactly what the compiler needs. `src/runtime/effects/io.ts`.
  - `feat(fibration)` — branches as Grothendieck fibers over the temporal log. `listBranches`, `computeBranchFiber`, `computeAllFibers`, `describeCartesianLift` in `src/runtime/fibration/branch-fiber.ts`. Read-only programmatic library; walker `:branch list` is the first surface, `onto branch list` is future work.
  - `feat(topos)` — three-valued Ω = `"true" | "false" | "unknown"` predicate algebra over node rules. `pAnd` / `pOr` / `pNot` / `pImplies` / `allOf` / `anyOf` / `atomProvides` / `atomRequires` / `atomForbids` build composable predicates; `compileNodeRules(node, neighborhood)` lifts a node's `requires` / `provides` / `forbids` into a single predicate; `evaluatePredicate(p, ctx)` returns Ω. `src/runtime/topos/predicate.ts`. Additive: `intent-validator.ts` and `gluing.ts` are unchanged.
- Compile-plan hardening — `contradicts` and `supersedes` (PR #112): `computeCompilePlan` now rejects any plan that closes over a `contradicts` edge as a hard `CompilePlanError` and halts BFS on `supersedes` with a `superseded` warning. Contradictions surface as failures rather than silent compiles. Pure helper, returns deterministic warnings/errors so scripts and the walker stay in sync.
- **PromptAST (PR #113): axiom 4 made structural.** `parsePromptAST(raw)` recognises three line-anchored markers — `@requires:`, `@provides:`, `@expand:` — strips them from the prompt body, and emits a `PromptAST` with deduplicated, ordered token lists. `compileNode` consumes the parsed `body` instead of the raw text, so prompts are now first-class **rewrite rules** rather than opaque strings. Closes the last "axiom 4 stored as text" gap.
- Walker hardening — `:validate`, `:branch list`, `:context`, `:query`, `:compile --runtime-check` (PR #114): the walker now exposes deterministic intent validation, branch-fiber listing (the first fibration CLI surface), explicit context assembly with the same edge filters as the CLI, ad-hoc Yoneda queries against the focal cell, and the optional runtime-check gate on inline compiles. Eight walker actions now live under `src/walker/actions/`.
- Compiler refactor onto `EffectWithLog` (PR #115): `compileNode` no longer wraps the dispatch / write / validate pipeline in a top-level `try/catch`. Each step is an `EffectWithLog`; failures bubble through `bindWithLog` so partial diagnostics survive and a step's log is non-empty even when the step record reports an error. The follow-up unlocked by Bootstrap 0.9 in `CATEGORICAL_VISION.md` is now shipped.
- **Walker `:graph view [depth]` action (post-0.9):** the terminal-first answer to the "Visual DAG Studio" follow-up. Renders the focal node's k-hop subgraph (default depth 2, capped at 5) as a structured panel with three buckets — Upstream (`↑`), Downstream (`↓`), Lateral (`↔`). Each row colored by abstraction-level via `POSET_COLORS`, with the `kind/abstraction` tag dimmed and up to 4 incident edges per row. Reuses `extractSubgraph` from the traversal helpers so the slice membership matches `onto graph subgraph` exactly. Buckets cap at 15 rows each; a `…N more node(s) hidden` hint appears when the slice is larger. Render is *structural*, not pictorial — no boxes-and-lines ASCII art. Helper at `src/walker/actions/graph-view-from-walker.ts`, parser at `src/walker/state/parse-graph-view-args.ts`. Dismiss with `:clearinfo`.
- **Semantic linker CLI + walker action (post-0.9):** new `onto link <nodeId> --candidate <text> | --candidate-file <path>` wraps `semanticLink()` and renders a single LINK card with the validation block (`ok`/`score`/`violations`/`warnings` from `validateIntent`), the per-token requires/provides/forbids matrix (with provider attribution from the in-scope fragments), one-hop relevant neighbors, and edge proposal suggestions for any unsatisfied requirement. Suggestions are emitted per provider with parallel rows for `depends_on` and `uses_token` and printed as copy-pasteable `onto propose link …` commands — the linker never auto-creates proposals. `--include-edges` / `--edge-types` extend the gluing pool, `--no-suggest-edges` suppresses the suggester, `--json` matches. Walker mirror: `:link-analysis` action defaults the candidate to `focal.prompt.raw` so the analysis is reachable without typing. Pure suggester at `src/runtime/context/edge-suggester.ts`. See [`CLI_COMMANDS.md`](CLI_COMMANDS.md) `link <nodeId>`.
- **Validator port onto topos algebra (post-0.9):** `intent-validator.ts` is now built on the predicate algebra in `src/runtime/topos/`. Each of the three validator rules (gluing ok, candidate non-empty, FORBID phrase scan) compiles to a `Predicate`; they fold via `allOf` and evaluate against an `EvaluationContext` synthesised by `buildEvaluationContext`. The high-level `IntentValidationResult` contract is preserved (`ok`, `score`, `violations`, `warnings`); a new `verdict: Omega` field exposes the underlying three-valued result. Externally observable behaviour stays Boolean (closed-world reduction); the lower-level `compileValidationPredicate` helper allows callers to evaluate against a partial context if they want to observe `verdict === "unknown"` directly. See [`RULES_TOPOS.md`](RULES_TOPOS.md) and [`MATHEMATICAL_CLAIMS.md`](MATHEMATICAL_CLAIMS.md) §3.9.
